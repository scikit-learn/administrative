### Callbacks API: post-RC work

Several pieces of callback infrastructure landed or are in review since the

- **Signature caching**
  ([#34099](https://github.com/scikit-learn/scikit-learn/pull/34099)):
  merged. Caches `inspect.signature` for callback hook evaluation to avoid
  repeated inspection overhead on every call.
- **Scoring monitor example**
  ([#34153](https://github.com/scikit-learn/scikit-learn/pull/34153)):
  merged. Gallery example showing how to use the `ScoringMonitor` callback

  combinations.
- **Hook validation at setup time**
  ([#34096](https://github.com/scikit-learn/scikit-learn/pull/34096)): open.
  Moves hook signature validation to `set_callbacks` rather than checking on
  every call. Reviews welcome.
- Jérémie du Boisberranger plans to close the current Callbacks API plan
  meta-issue and replace it with focused, actionable issues to make progress
  easier to track.
- **Callbacks as metadata routers**
  ([#34137](https://github.com/scikit-learn/scikit-learn/pull/34137)): open,
  not expected to merge before the 1.9.0 final release. François Paugam is
  working on making callbacks act as metadata routers. The approach requires
  every estimator to become a metadata router if it is to support callbacks,
  which the team considers the only architecturally consistent path — but
  given the scope, **wider community consultation is needed before finalising
  the design**. Input is very welcome.

### Thread safety and oversubscription

Two related performance and correctness threads are active:

- **Thread-safety testing**
  ([#34057](https://github.com/scikit-learn/scikit-learn/pull/34057)):
  Itamar Shtayer (NASA grant) is developing tooling to detect mutation during
  parallel calls, plus a fix for one race condition already found. The PR is a
  draft and reviews are welcome.
- **Oversubscription on hybrid-core CPUs**: a catastrophic interaction between
  OpenMP and OpenBLAS's active-wait policy combined with efficiency cores on
  recent CPUs (Mac, Intel) can inflate runtimes from ~2 s to over a minute for
  gradient-boosted models, KNNs, and NMF. This is worse with PyPI installs
  than conda-forge. Ongoing work in
  [loky](https://github.com/joblib/loky/pull/630) aims to detect and use only
  performance cores for scheduling to mitigate this.

### macOS CI: BLIS numerical errors

A lock-file update caused `conda install numpy` to default to the BLIS backend
instead of OpenBLAS on macOS, producing incorrect numerical results.
The fix is to pin the CI configuration to OpenBLAS. A standalone (non-Python)
reproducer is being prepared to report the issue upstream to the BLIS
developers.

### Array API: classifiers and sparse tensors

- **Classifier string labels**: on-device computation with string targets

  across classifiers and classification metrics is planned to ensure consistent
  behaviour once this is resolved.
- **Sparse tensor support**: after discussion, the team agreed to document
  that sparse tensors are not currently supported rather than attempting a
  technical solution.
